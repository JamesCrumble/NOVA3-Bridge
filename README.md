# NOVA3 Bridge

**English:** run **N.O.V.A. 3 1.0.7** (Gameloft, 32-bit ARMv7) on 64-bit-only Android phones that have no
AArch32 support. The game runs under a patched `qemu-user`, and its OpenGL ES calls are forwarded to the phone's
real GPU. Tested on a OnePlus 13s (Snapdragon 8 Elite). No game files are included: you need your own copy.
Ready-made APK: [Releases](https://github.com/JamesCrumble/NOVA3-Bridge/releases).
The rest of this page is in Russian.

Запуск 32-битной **N.O.V.A. 3** (Gameloft, v1.0.7, только `armeabi-v7a`) на 64-битных Android-телефонах, в которых
нет поддержки AArch32. Проверено на OnePlus 13s (Snapdragon 8 Elite, Android 15).

Игра исполняется в собственном пропатченном `qemu-arm` (linux-user), а её вызовы OpenGL ES пробрасываются
на настоящий GPU телефона. Звук, касания, геймпад, пауза и возврат в приложение работают.

**Игра не распространяется.** Нужны ваши собственные APK версии 1.0.7 и два файла OBB.

## Состояние

- Игра проходится: меню, кампания, бой.
- Скорость на OnePlus 13s при рендере 720p: меню и лёгкие сцены до 90 fps и выше, в бою заметно ниже и зависит
  от сцены (замеры в бою до сборки qemu F: 25–55 fps; после неё бой отдельно не перемерялся).
- Заставка на титульном экране рисуется в левом верхнем углу; меню и игра — во весь экран.
- Загрузки долгие: распаковка данных идёт под эмуляцией.
- Проверено на одном устройстве. На других чипах возможны отличия в драйвере GLES.
- 0.6 исправляет падение при запуске, о котором сообщили с телефона на Mali-G57 MC2 (SIGSEGV сразу после
  `GDRM lock words` в логе). Если 0.5 падает так же, обновитесь.

Скорость ограничивает не GPU, а процессор: игра упирается в один поток, а Android держит частоту ядер ниже
максимума (см. [Производительность](#производительность)).

## Установка

Готовая сборка лежит на странице [Releases](https://github.com/JamesCrumble/NOVA3-Bridge/releases):
`NOVA3-Bridge-<версия>.apk` и `INSTALL.txt`.

1. Установите APK (пакет `com.jamescrumble.nova3`), запустите один раз и закройте: появится папка
   `/sdcard/Android/data/com.jamescrumble.nova3/files/`.
2. Положите в неё два файла как есть: оригинальный APK игры 1.0.7 и zip-архив с её кэшем. Имена не важны.
3. Откройте приложение, при необходимости поменяйте настройки и нажмите «Играть».

Первый запуск долгий: из архива распаковываются оба файла `.obb` (около 2,3 ГБ), затем sysroot (~100 МБ) и
библиотеки игры. Если что-то не так, причина пишется на экране и в `nova3.log` в той же папке.

Вместо архива можно положить туда же два готовых файла `.obb` (`main.1050…` и `patch.1070…`); по-прежнему
подходит и папка `/sdcard/Android/obb/com.jamescrumble.nova3/`.

**Обновление со старого имени пакета.** До версии 0.3 пакет назывался иначе, и для Android это другое приложение:
поверх оно не обновится. Прогресс переносится так: сборка `APP_ID=<старый пакет> tools/build_install.sh noinstall`
обновляет старое приложение и на его экране настроек выгружает сохранения в папку `migrate` рядом с файлами игры;
эту папку нужно переложить в `Android/data/com.jamescrumble.nova3/files/`, новое приложение заберёт её при запуске игры.

## Настройки

Экран настроек открывается при старте приложения. Значения хранятся в `settings.txt` рядом с файлами игры.

| Настройка | Ключ | Что делает |
|---|---|---|
| Угол обзора (FOV) | `NOVA3_FOV_PERCENT` | 100–220 %, по умолчанию 160; 100 % — как в оригинале |
| Разрешение рендера (высота) | `RENDER_HEIGHT` | 480 / 540 / 720, по умолчанию 720; выше интерфейс игры ломается |
| Лимит кадров | `FPS_LIMIT` | 30 / 60 / 90 / 120, по умолчанию 60; та же частота запрашивается у экрана |
| Счётчик FPS | `FPS_COUNTER` | Показывает fps поверх игры |
| Тени | `Q_SHADOWS` | Выключение разгружает процессор и видеокарту |
| Пост-эффекты | `Q_POST` | DOF, туман, блюр, искажения: дополнительные проходы рендера |
| Дальность детализации (LOD) | `Q_LOD` | 30–100 %; меньше — упрощённые модели ближе к камере |
| Уровень деталей | `Q_DETAILS` | 0 — полный, 2 — минимальный |
| Буфер звука | `AUDIO_LATENCY_MS` | Размер буфера AudioTrack |
| Кадров «в полёте» | `NOVA3_GL_INFLIGHT` | Сколько кадров мост может держать в очереди к GPU, по умолчанию 2 |
| Физика в отдельном потоке | `NOVA3_PHYSICS_THREAD` | Разгружает главный поток; по умолчанию выключено |
| Только быстрые ядра (6–7) | `CPU_PRIME` | Привязывает qemu к двум самым быстрым ядрам; по умолчанию выключено |
| Подсказки производительности (ADPF) | `PERF_HINT` | Сообщает системе длительность кадров против цели из лимита кадров; по умолчанию выключено |
| Профилирование в логе | `QEMU_GUEST_PROF` | Диагностика, см. ниже |

## Как это устроено

```
 APK-обёртка (Java, AArch64)                    дочерний процесс
 ┌──────────────────────────────┐   pipe   ┌─────────────────────────────────────────┐
 │ SettingsActivity             │ ◄──────► │ qemu-arm (наш патч, статический AArch64) │
 │ MainActivity + SurfaceView   │  команды │  └ nova3 (порт-лоадер, ARM32, glibc)     │
 │ GlBridge: исполняет GLES     │   GLES   │      ├ bionic ELF loader                 │
 │ AudioTrack, касания, геймпад │          │      ├ libNOVA3_neon.so (игра)           │
 │ PerfHint (ADPF, телеметрия)  │          │      ├ JNI и Android API на заглушках    │
 └──────────────────────────────┘          │      └ GL-мост: сериализует вызовы GLES  │
                                           └─────────────────────────────────────────┘
```

- **Порт-лоадер** (`port/game/`, `port/portbase/`) загружает библиотеку игры, собранную под bionic, в процесс
  с glibc и подменяет libc, JNI и системные вызовы Android. Это порт N.O.V.A. 3 для PortMaster.
- **GL-мост** (`port/portbase/src/gl_bridge.cpp` ↔ `port/android/src/.../GlBridge.java`): вызовы GLES пишутся в pipe
  и исполняются на стороне Java в контексте GLES 3 на SurfaceView.
- **Звук**: OpenSL ES порта → FIFO → AudioTrack напрямую, темп задаёт динамик телефона.
- **qemu** (`qemu/`): QEMU 11.1.2 с нашим патчем, см. ниже.

Подробный журнал разработки, выводы и тупиковые ветки — в [PROJECT_STATE.md](PROJECT_STATE.md), история версий —
в [CHANGELOG.md](CHANGELOG.md), архитектура обёртки — в [port/android/README.md](port/android/README.md).
Пошаговый разбор — что было видно, как нашли причину, что исправили — в
[docs/PORTING_GUIDE.md](docs/PORTING_GUIDE.md) ([English](docs/PORTING_GUIDE.en.md)).

## Производительность

Штатный qemu исполняет игру слишком медленно, поэтому используется QEMU 11.1.2 с набором правок под
AArch64-хост (подробно в [qemu/README.md](qemu/README.md)):

- **Плавающая точка на процессоре телефона.** Скалярные VFP-операции add/sub/mul/div вставляются прямо
  в сгенерированный код одной командой, без вызова функции. Остальные операции VFP и преобразования float↔int
  считаются одной командой процессора внутри хелпера вместо softfloat.
- **NEON f32 целым регистром.** Сложение, вычитание, умножение, умножение с накоплением, сравнения и min/max
  считаются сразу для всех четырёх элементов на NEON телефона, без переключения режима FPCR.
- **Флаги и сравнения в коде.** Сравнения VCMP и запись флагов NZCV(Q) делаются в сгенерированном коде.
- **Косвенные переходы.** Быстрый поиск блока для возвратов и вызовов по указателю: флаги собираются
  на месте, кэш переходов увеличен с 4096 до 65536 записей и хранит всё нужное для попадания.
- **Сцепление блоков** напрямую через границу страницы.
- Обходы ограничений Android: системные вызовы, которые фильтр seccomp приложений запрещает, не используются.

Точность плавающей точки проверяется тестами `qemu/fptest.c`, `cmptest.c`, `neontest.c`, `neoncmptest.c`:
результат должен совпадать с `QEMU_STRICT_FP=1` (чистый softfloat).

Со стороны моста: кэш состояния GL, информация о шейдерной программе одним запросом, вершины общего массива
передаются один раз, для индексных отрисовок — только используемый диапазон.

Главный ограничитель на OnePlus 13s — политика энергосбережения системы: она опускает потолок частоты ядер
при холодном телефоне, и fps идёт за этим потолком. Из приложения снять это ограничение не удалось.

## Сборка

Сборка идёт в WSL (Ubuntu).

Нужны, кладутся в корень проекта и в git не входят:

- `jdk/` — JDK 17;
- `android-sdk/` — build-tools 34.0.0, platform 34, platform-tools;
- `sdl-arm/` — SDL2 под armhf;
- системный armhf-тулчейн (`gcc-arm-linux-gnueabihf`, `g++-arm-linux-gnueabihf`) и Docker для qemu;
- `port/gamebin/` — ваш APK игры, `nova3data/` — её OBB (нужны скрипту релиза и для запуска на ПК).

```sh
source env.sh
tools/build_install.sh             # порт + APK + установка на телефон по adb
tools/build_install.sh noinstall   # то же без установки
tools/make_release.sh              # релизный APK, архив исходников и INSTALL.txt в release/<версия>/
```

Телефон из WSL виден через виндовый `adb.exe`: используйте обёртку `tools/adb`.

### qemu

Исходники QEMU 11.1.2 распаковываются в `qemu-src/qemu-11.1.2` (`tools/qemu_fetch.sh`), на них по порядку
накладываются `qemu/patches/nova3.patch`, `neon_nofpcr.patch` и `fast_fp_inline.patch`.

```sh
docker build -t nova3-qemu-build qemu
docker run --rm -u 1000:1000 -e HOME=/tmp -v "$PWD":/work nova3-qemu-build \
  bash /work/qemu/build_variant.sh F \
  '-DNOVA3_JMP_BITS=16 -DNOVA3_FAST_LOOKUP -DNOVA3_NEON_NOFPCR -O3 -march=armv8.2-a+lse+rcpc+dotprod -mtune=neoverse-v1'
```

Результат — `qemu/out/qemu-arm-F.stripped`, его забирает сборка APK; `NOVA3_QEMU_VARIANT=D` собирает APK
с прежним вариантом. Не добавляйте SVE в `-march`: у ядер Oryon его нет. Наложение трёх патчей на чистые
исходники с нуля не перепроверялось: вариант F собран в дереве проекта Shadowgun Bridge и перенесён сюда файлом.

## Диагностика

- Лог игры: `tools/pull_log.sh` → `logs/phone.log`. Строка `[gl] frames` раз в несколько секунд показывает fps,
  число GL-команд, загрузку моста, текущую частоту и потолок частоты ядра, `uclamp`.
- Быстрый просмотр fps и поиск по логу: `tools/fps.sh`, `tools/grep_log.sh`.
- Профиль кода игры пишется в лог, пока включена настройка «Профилирование в логе».
- Профиль самого qemu: `tools/profile.sh <секунд>` (simpleperf; приложение `profileable`).
- Частоты, ядра и температуры: `tools/cpu_diag.sh`.
