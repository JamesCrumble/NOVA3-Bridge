# NOVA3 Bridge

Обёртка совместимости: 32-битная Android-игра N.O.V.A. 3 (1.0.7, armeabi-v7a) работает на 64-битных
телефонах без поддержки AArch32 (проверено на OnePlus 13s, Snapdragon 8 Elite) через собственную
эмуляцию CPU и проброс графики на настоящий GPU телефона. Игра не распространяется: нужны свои APK и OBB.

## Архитектура

```
 APK com.eaprules.nova3 (Java, без NDK)                        Телефон: Oryon (только AArch64), Adreno 830
 ┌───────────────────────────────────────────────────────┐
 │ MainActivity   SurfaceView + оверлей (FPS, загрузка)  │
 │                мультитач/кнопки/геймпад → команды     │
 │ GameProcess    распаковка sysroot, OBB, запуск qemu,  │
 │                ctl/commands, status.json, звук        │
 │ GlBridge       поток nova3-gl: EGL + GLES 3.0,        │◄── pipe gl_cmd  (поток команд, 1 МБ)
 │                проигрывает GL-команды игры на GPU     │──► pipe gl_reply (ответы на запросы, ack кадра)
 │ PerfHint       ADPF-сессия на потоки qemu, телеметрия │
 └───────────────────────────────────────────────────────┘
                 │ ProcessBuilder (дочерний процесс)
                 ▼
 libqemu.so = наш qemu-arm 11.1.2 (статический aarch64, патчи: быстрый float/NEON, быстрый поиск переходов)
 ┌───────────────────────────────────────────────────────┐
 │ гостевой ARM32-мир (armhf, транслируется в AArch64)   │
 │  bin/nova3  — порт-лоадер: загружает .so, фейковый    │
 │             JNI и Android API (EGL, OpenSL, AAsset…)  │
 │  sysroot/   — armhf glibc, SDL2 и др.                 │
 │  game/lib/armeabi-v7a/libNOVA3_neon.so — сама игра    │
 │  game/<obb> — данные (симлинки на Android/obb)        │
 └───────────────────────────────────────────────────────┘
```

Каналы между процессами:

| что | как |
|---|---|
| графика | 2 FIFO-пайпа: команды GL туда, ответы на синхронные запросы и подтверждения кадров обратно |
| ввод | текстовый файл `ctl/commands` (`touch 1 x y id`, `key 4 down`, `pad 1`…), порт читает каждый кадр |
| состояние | `ctl/status.json` (кадр, меню/игра) |
| звук | SDL «disk» → FIFO → `AudioTrack` |
| настройки | файлы рядом с логом (`gpu_name.txt`, `engine_env.txt`, `xml_override.txt`, `cpu_mask.txt`…) и переменные окружения |

### Путь графики

1. Игра вызывает GLES 2.0 (`glDrawElements`, `glUniform…`). Внутри qemu эти вызовы попадают не в
   драйвер, а в заглушки моста (`portbase/src/gl_bridge.cpp`, ARM32-код).
2. Мост кодирует вызов в компактное сообщение в буфере:
   - имена объектов (текстуры, буферы, шейдеры) раздаёт сам гость, хост переводит их в настоящие;
   - клиентские массивы вершин копируются прямо в сообщение draw (сейчас 2–7 МБ на кадр);
   - повторные смены состояния и одинаковые uniform отсеиваются ещё до отправки.
3. Синхронные запросы (статус шейдера, `glGet*`, `glReadPixels`) сбрасывают буфер и ждут ответа.
   Их мало: информация о программе забирается одним запросом при линковке.
4. На стороне Java поток `GlBridge` читает поток команд и исполняет их через `GLES30` на GPU.
   Рендер идёт в `SurfaceView` фиксированного размера (~1544×720 под пропорции экрана),
   композитор растягивает картинку на весь экран.
5. На `swap` хост показывает кадр и шлёт подтверждение; гость может обгонять хост максимум на 1 кадр.

### Ввод

Для движка телефон — обычный сенсорный смартфон (`NOVA3_TOUCH=1`, PowerA-геймпад «не подключён»):
игра рисует свой сенсорный HUD, касания идут в `touchEvent` с кодами самого движка
(1 — палец вниз, 2 — движение, 0 — палец вверх) и id пальца. «Назад» передаётся игре (keycode 4).
При первом событии от физического геймпада обёртка сообщает движку `pad 1` и переходит на раскладку геймпада.

### Где сейчас узкие места

- CPU, один поток: главный поток игры в qemu. GPU загружен на 15–45%, видеокарта простаивает.
- Лимитер частот OxygenOS: приложение не в списке игр, поэтому потолки ядер скачут от 1,2 до 2,6 ГГц.
- Трансляция ARM32 → AArch64: оставшиеся крупные статьи — поиск переходов (~15%) и выходы на
  системные вызовы, включая лишний опрос `libudev` в SDL.

## Установка

После установки APK положить свои файлы игры:

```text
/sdcard/Android/data/com.eaprules.nova3/files/
  N-O-V-A-3-Near-Orbit-Vanguard-Alliance-v1-0-7.apk
/sdcard/Android/obb/com.eaprules.nova3/
  main.1050.com.gameloft.android.ANMP.GloftN3HM.obb
  patch.1070.com.gameloft.android.ANMP.GloftN3HM.obb
```

Первый запуск распаковывает sysroot (~100 МБ) в приватное хранилище и подключает OBB симлинками без
копирования. Игра дополнительно распаковывает свои ассеты (до нескольких ГБ). До главного меню показывается
экран загрузки, звук до этого выключен.

Для производительности полезно: в настройках приложения разрешить фоновую активность, включить системный
режим высокой производительности, добавить игру в приложение «Игры» (Games).

## Сборка

```sh
# WSL, из корня репозитория. Нужны: build/nova3 (порт), Android SDK build-tools 34.0.0 + platform 34,
# JDK 8+ (javac), python3. QEMU_BIN — наш qemu-arm (см. qemu/README.md); без него берётся Debian 7.2.
QEMU_BIN=/path/to/qemu-arm.stripped JAVA_HOME=/path/to/jdk bash android/build_apk.sh
```

Результат: `NOVA3-ARM32-debug.apk` в корне репозитория. Ключ отладочной подписи хранится в
`android/build/debug.keystore`, так что пересобранные APK ставятся поверх. Патч qemu, его сборка в Docker,
тест точности float и бенчмарк — в `qemu/`.

## Настройки и отладка

Всё лежит в `Android/data/com.eaprules.nova3/files/`:

| файл | назначение |
|---|---|
| `nova3.log` | лог игры и обёртки; раз в 5 с строка `[gl] frames …` с FPS, ядром/частотой qemu и статистикой моста |
| `gpu_name.txt` | подменяет GL_RENDERER: по нему движок выбирает профиль качества |
| `xml_override.txt` | строки `было=>стало`: правка XML движка (профили качества) перед разбором |
| `xmldump.flag` | сохранять все разбираемые XML в `xmldump/` |
| `engine_env.txt` | строки `KEY=VALUE` в окружение порта (`NOVA3_GAME_LOG=1`, `NOVA3_GL_PROFILE=1`, …) |
| `cpu_mask.txt` | hex-маска ядер (например `c0`): закрепить qemu через `taskset` |
| `resolution.txt` | размер рендера, например `1280x590` |
| `pad_overlay.flag` | вместо родного сенсорного HUD — оверлей в стиле геймпада |
| `notrace.flag` | выключить трассу загрузчика |
| `qemu_args.txt` | дополнительные аргументы qemu, по одному на строку (например `-strace`) |
| `diag_cmd.txt` | shell-скрипт вместо игры (`$QEMU`, `$STRACE`, `$ROOT`); `$STRACE` — `mstrace` из `android/tools/mstrace` |

Переменные qemu: `QEMU_STRICT_FP=1` выключает быстрый float, `QEMU_SYSCALL_STATS=1` раз в 10 с пишет в лог
топ системных вызовов гостя.

## Ограничения устройства

- Seccomp-фильтр Android убивает процесс приложения за системные вызовы вне белого списка bionic.
  `android/patch_syscalls.py` переписывает в статическом glibc qemu вызовы `set_robust_list`, `rseq` и
  `faccessat2`; сам qemu не вызывает `realpath` (а с ним `faccessat2`) на каждом `open`.
- qemu-user не загружает гостевую программу без бита исполнения, поэтому обёртка ставит его на `bin/nova3`
  и гостевой `ld.so` после распаковки.
- qemu-user печатает ошибки загрузки через `printf` и выходит через `_exit`, при перенаправленном stdout
  они теряются; `mstrace` достаёт их из памяти.
- Запускать исполняемый код Android разрешает только из каталога нативных библиотек приложения, поэтому
  qemu лежит в APK как `libqemu.so`.
